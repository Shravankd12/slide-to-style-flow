Letters of credit · product flow

A clear path from request to human decision.

SG TradeFlow brings customers and trade operations into one application workspace. Documents stay private to their LC case; automated assistance prepares review data, while people and database-enforced controls own every trade decision.

Design principle

Automation can organize the work. Only authorized people can review, clear compliance, and approve or reject an LC.

Review is a gate, not a finish line.

02

Approval gates

Decision rules live in PostgreSQL functions and triggers—not just in UI labels.

1Officer request

Requires at least one document, extraction fields, reviewed low-confidence values, resolved discrepancies, and answered clarifications.

2Compliance clearance

A database trigger blocks approval when an application has a compliance flag that is not cleared by a human reviewer.

3Approver decision

Only an approver or admin can decide a pending request. An approved or rejected decision requires a reason.

4Traceable outcome

Decision and review functions write audit events. Approval produces a validated draft; it does not transmit a SWIFT message.

03

Application & data layers

The route, server adapter, database, and private file store each have a clear responsibility.

What runs where

  • ExperienceTanStack Start / React shared route at /; role-filtered navigation and case detail.
  • AuthenticationSupabase Auth; user_roles distinguishes customer, officer, approver, compliance, and admin.
  • ServerAuthenticated server function validates ownership and status before demo processing.
  • DatabasePostgres / Supabase with RLS, decision RPCs, audit history, notifications, and approval guard triggers.
  • FilesPrivate lc-documents bucket; paths begin with the application ID and reads use short-lived signed URLs.

Role responsibilities

  • CustomerCreate and view own LC applications, upload documents, answer clarifications.
  • OfficerReview extraction, resolve discrepancies, request clarification, submit complete cases for approval.
  • ApproverApprove or reject pending requests with a recorded reason.
  • ComplianceRecord reasoned human outcomes on flagged cases; only clearance unblocks issuance.
  • AdminManage roles and stored settings through admin-checked database functions; settings cannot bypass review.
04

Supporting operations

Cross-cutting signals follow the case without replacing the decision path.

Audit & notifications

Application activity is recorded for key events. In-app notifications remain available to signed-in users.

Email is an integration point

External email delivery requires provider/script configuration and deployment; queued or mock email is not proof that a message was sent.

Configuration is not validation

Administration settings are stored preferences. They do not run file-content analysis or disable mandatory human approval.
